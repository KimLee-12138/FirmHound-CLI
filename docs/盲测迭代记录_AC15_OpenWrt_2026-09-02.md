## 2. 发现的 CLI 缺陷与修复（3 处，全部已落代码）

1. **攻击面提取器单词级误报（P0）** — `tools/web/handler_extract.py`
   `GOAHEAD_RE = \b(form|from)(\w{2,})\b` 对每个 ELF 字符串做单词匹配，`format` 等普通英文词
   把 `/goform/format` 面挂到 libc/busybox/内核模块/udevd 等一切文件。
   **实测铁证**：全 AC15 rootfs 只有 `bin/httpd` 含字面 `/goform/`（偏移 868436）；libc 无 `/goform/` 却含 `format`。
   **修复**：① 文件须含字面 `/goform/`（或 `websFormDefine` 注册）才产 CGI 面；② handler 须含大写/下划线（滤 `format`/`forms` 类小写英文词）。

2. **候选→面按 basename 匹配导致串面（P1）** — `tools/audit/static.py` `_matching_surface`
   原逻辑 `Path(surface.binary).name == Path(summary.path).name`：同名不同目录的文件互相串面；httpd 有 150 个面却只取第一个。
   **修复**：按 rootfs-relative **全路径精确匹配**（含 daemon 面），偏好「handler 出现在该二进制字符串样本中」→ 再偏好 preauth。

3. **内核模块/共享库混入候选（P1）** — `tools/audit/static.py` 候选循环
   `.ko` 被当用户态二进制出候选，top 分曾给 `_raw_write_lock_bh`（内核符号）；`.so` 同理。
   **修复**：候选生成前跳过 `*.ko` 与含 `.so` 路径。

4. **（v3 附带观察）** 静态度下每二进制「源+sink 全共现」仍会出多候选（httpd 一个二进制就 ~47 个 cmdi/溢出候选，因 strip 无函数边界）；ranking 中 `open/fwrite`（flash 写工具）被评到 16 分 > httpd `doSystemCmd/popen` 15 分——**评分的攻击性偏向 filesystem sink**，列入 backlog。

## 3. 当前盲测结论（诚实版）

- **AC15 v3**：849 候选收敛到真实 ELF 集；`bin/httpd`（bin-4ff83a811405）的 command_injection
  （doSystemCmd/system/popen/execve）候选全部**正确映射到 httpd 的 preauth CGI 面**（当前取
  `surf-944d8cd4=/goform/formWifiConfigGet`——无反编译器时只能做到"面在正确的二进制上"，
  具体 handler 归属需反编译确认；已知 `formexeCommand` 面存在于攻击面且 httpd 含 `doSystemCmd` 导入）。
- **但 verifier 仍全 DOWNGRADE**（top-5 → 3~6 分）：原因单一——`call-chain-not-proven`。
  这是**纯静态、无反编译器**的硬上限：没有调用链证据，10 问反证必杀。
- **OpenWrt v1**：面 370（368 条是 procd 式启动解析噪音，如 `[`/`grep`/`rcS` 被当 daemon——backlog）；
  候选仅 2 个（uhttpd/luci 补丁到位，低信号属合理）。

## 4. v4 — 接入 ARM32 调用链恢复（决胜项第一步，2026-09-02 下午）

**新增 `tools/binary/call_chain.py`**（capstone + pyelftools 纯 Python，无 Ghidra）：线性扫描 .text，
经 PLT（头长由 `plt_size - N×12` 动态推导）解析导入名，定位每个 sink 调用点及其**所属函数**
（`push {..,lr}` 前导界定），并做**同函数** source/filter 共位检测。全反汇编 httpd(830KB) 约 3s。

**实测定量（httpd）**：sink 调用点 1130 个——sprintf 784 / doSystemCmd 181 / strcpy 159 /
system 3 / popen 2 / execve 1，均锚定到所属函数（如 doSystemCmd 一处位于 sub_2e420）。

**集成进 `tools/audit/static.py`**（`_enrich_with_chain`）：候选若在该 ELF 找到「所属函数调用此 sink」，
则写入真实 `call_chain`（[sub_X → sink 调用点]）、按**同函数** filter 重算 validation、
移除占位 `call-chain-not-proven` 反证、追加 decompile 证据。找不到则保持诚实降级不编造。

**AC15 v4 结果（verdict 翻转）**：
| 候选 | v3 | v4 |
|---|---|---|
| httpd popen/execve cmdi（如 cand-27a8dd656711） | DOWNGRADE 15→5 | **NEED_DYNAMIC 16→16**（chain_len=2，ce=[]） |
| unmapped 的 open/fwrite path_traversal | DOWNGRADE | DOWNGRADE（fs sink 无链，backlog） |

即：httpd 的 system/popen/execve/doSystemCmd 候选现在拿到**反汇编证实**的 sub_X→sink 链，
verifier 判定为"静态证据充分、需动态验证"（走 LOCAL_VALIDATION/BOND），不再是无差别砍分。
这是"能不能确认漏洞"的分水岭：静态层已到能力上限，剩最后一步是**把 handler 名还原**
（websFormDefine 在本固件为静态链接、非 PLT 导入，注册表解析暂不可用 → backlog 榜首）。

**过程中又修 2 个自身 bug**：① evidence_store.add 返回 dict，曾误 append 整 dict 进 evidence → RANK 崩
（`'dict' object has no attribute 'lower'`）；② 证据 type 用 `decompile`（枚举外值被 schema 拒）。
另记状态机遗留：REPORT 完成后 `run_state.status` 停在 `running`/current=REPORT 未置 done（不影响产物，backlog）。

## 7. v5/v6 — 一次性迭代剩余 backlog（2026-09-02 晚，用户"一次都做好"）

1. **状态机 REPORT→DONE**：上游 engine.run/resume 已带 DONE 收尾（本会话核验）；v6 起 `status: done` 正常。
2. **注册表/name 还原调研结论（诚实）**：websFormDefine 静态链接 + 字符串 `formexeCommand` 在
   ARM/Thumb/movw-movt/ldr/ADR/静态表 六种引用形态下全零引用、`.rel.dyn` 无 RELATIVE → 本固件 handler
   名↔函数绑定**无静态可解路径**（疑似运行时集中构造调度表），需 Ghidra 级分析；不硬造。`call_chain`
   注册表扫描已泛化（任意被调函数 r0=form*+r1=code），在存在常规注册模式的固件上即可出名字。
3. **性能**：注册表扫描原实现每调用点全节区遍历 + 逐字节读串 → 慢 10 倍；改为节区视图一次建好 +
   rodata 范围预判 + 128B 单次读 + 字符串缓存 → httpd 恢复 3.7s。
4. **评分/候选去偏**：`static.py` fs 类 sink 且无映射面 → 直接不发（updater/mtd 噪音清零）。
5. **OpenWrt procd 噪音**：`startup_parse` 增加 inittab 冒号行处理、shell 内建/短命命令 ignore 名单、
   `start-stop-daemon -x` 解析。
