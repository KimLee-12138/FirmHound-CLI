# 外部四工具接入核验记录（2026-09-02）

## 1. 结论

四个外部工具已经完成 FirmHound CLI 层面的接入：

- SaTC
- FirmRec
- KLEE
- mini-BOND

这里的“接入成功”指：

1. CLI/Orchestrator 能通过统一 registry 调到对应工具。
2. 每个工具都有 adapter/runner/parser 或等价实现。
3. 工具缺失时返回结构化 skipped/degraded，不会让主链崩溃。
4. 外部发现可以进入统一产物目录。
5. FUSION/KLEE/BOND/FirmRec 隔离规则有测试覆盖。

但当前 Windows 本机环境尚未完成四个真实重型工具的生产级运行：

- Docker daemon 当前不可用，SaTC/FirmRec Docker 后端 degraded。
- KLEE 本机命令不可用。
- Ghidra `analyzeHeadless` 不可用。
- mini-BOND 的仿真生产模式未配置，simulation 被明确排除为生产 finding。

因此材料中建议写：

> 四个外部工具已完成统一适配、解析、融合和降级接入；真实工具复现需要在具备 Docker/Ghidra/KLEE/仿真目标的 Linux 环境中开启。

不要写：

> 四个外部工具已经在当前机器上全部真实跑通并产生真实漏洞结果。

## 5. 材料建议口径

建议突出：

- 四工具不是简单拼接，而是被纳入统一证据契约。
- 缺工具时不崩溃、不伪造。
- FirmRec 和 Blind Run 隔离，防止“答案库式发现”。
- KLEE 不直接删候选，只写反证，防止误杀。
- BOND 不打真机，只允许授权仿真和无害 marker。

最适合写进 PPT 的一句话：

> 外部工具不是我们的噱头，而是证据链的补强器；能跑时贡献证据，不能跑时记录边界，不污染最终结论。
