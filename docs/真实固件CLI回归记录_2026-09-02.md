## 本轮暴露并修复的 CLI 问题

1. `binwalk` 输出解析不兼容经典三列表格，导致 AC15 的 TRX/LZMA/SquashFS 签名被漏掉。已支持经典表格和带 `|` 的表格两种格式。
2. `binwalk --signature --term` 在 WSL wrapper 场景下可能悬挂。已改为非交互 `binwalk <path>` 并设置扫描超时。
3. fallback 只切片、不解包，无法从 TRX/uImage/custom header 后的内嵌 SquashFS 恢复 rootfs。已改为“按文件系统魔数切片 → 对切片尝试 unsquashfs/sasquatch/UBI 解包”。
4. fallback 会切出大量 gzip 噪声。已限制 gzip 命中，并在加密固件场景跳过 gzip 噪声 carving。
5. `unsquashfs/sasquatch` 的输出目录不能预先存在，否则会失败或出现“返回成功但目录为空”。已按工具行为准备输出目录，并将空输出的成功判为失败。
6. Windows 下固件 rootfs 的 Linux symlink 可能触发 `WinError 1920`。已让 rootfs 评分器容忍不可访问 symlink，并兼容 `etc_ro`、`webroot_ro` 等厂商只读布局。
7. `fsa plan --firmware-path` 过去可能接受不存在路径。已改为早失败，减少比赛演示误操作。
8. CLI 现在可通过 `config/dev.yaml` 的 `tools.use_wsl_wrappers` 自动加载 `tools/wsl_wrappers`，`fsa doctor` 能看到 WSL 中的 `binwalk/unsquashfs`。

## 固件分析摘要

### Tenda AC15

- 解包结果：从 offset `0x1C9E98` 切出 SquashFS，使用 sasquatch 解出 rootfs。
- rootfs 评分：10，confidence 1.0。
- 关键组件：`bin/httpd`、`etc_ro/init.d/rcS`、`webroot_ro/`。
- CLI 发现：645 个静态候选，top 5 verdict 中 3 个为 `NEED_DYNAMIC`，主要集中在 `bin/httpd` 的 `/goform/formWifiConfigGet` 相关命令执行/内存安全候选。
- 注意：当前结论是静态候选，不等同于已确认漏洞；要确认需要在隔离仿真环境里做动态验证。

### OpenWrt WE826

- 解包结果：成功恢复 SquashFS rootfs。
- rootfs 评分：8，confidence 1.0。
- CLI 发现：357 个攻击面条目、166 个二进制，未生成高风险候选。
- 结论：作为标准 OpenWrt sysupgrade 样本，当前 CLI 能稳定跑完整链路。

### Tenda BE3LPro

- binwalk 签名：offset `0x204` 出现 `OpenSSL encryption, salted`，文件内 `Salted__` 头确认。
- CLI 行为：保存加密载荷切片 `tmp/real-be3lpro-20260902-r2/unpacked/encrypted_openssl_516.bin`，并明确返回“需要解密材料”。
- 下一步：需要厂商解密密码/密钥、升级工具中的解密逻辑，或用户提供已解密后的中间固件，再继续 rootfs 恢复和漏洞扫描。
