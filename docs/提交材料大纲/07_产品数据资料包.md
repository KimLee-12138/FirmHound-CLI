## 2. CLI 命令数据

当前 CLI 命令：

| 命令 | 用途 |
|---|---|
| `fsa doctor` | 检查本地运行环境、Schema、runtime、外部命令 |
| `fsa plan` | 解析自然语言任务和参数，生成执行计划，不执行分析 |
| `fsa analyze` | 分析固件镜像或 rootfs |
| `fsa status` | 查看运行状态 |
| `fsa resume` | 从中断阶段恢复 |

- `--config`
- `--input-type auto|firmware|rootfs`
- `--depth quick|standard|full`
- `--authorization-holder`
- `--authorization-scope`
- `--allow-emulation`
- `--vendor`
- `--model`
- `--version`
- `--run-id`
- `--json-output`

## 10. 本轮真实固件测试暴露并修复的问题

| 问题 | 修复 |
|---|---|
| binwalk 经典三列表格解析不兼容 | 支持经典表格和 `|` 表格 |
| binwalk WSL wrapper 场景可能悬挂 | 改为非交互扫描并设置超时 |
| fallback 只切片不解包 | 增加魔数切片后自动尝试解包 |
| gzip 噪声过多 | 限制 gzip 命中并在加密场景跳过噪声 |
| unsquashfs/sasquatch 空输出误判成功 | 空目录成功被判失败 |
| Windows symlink 导致 rootfs 评分异常 | rootfs 评分器容忍不可访问 symlink |
| `fsa plan --firmware-path` 接受不存在路径 | 改为早失败 |
| WSL wrapper 配置不直观 | `doctor` 可看到 WSL 中 binwalk/unsquashfs |

可以写：

- “FirmHound 已实现面向 IoT 固件漏洞挖掘的 CLI 智能体流水线。”
- “系统默认使用确定性离线规则，避免模型幻觉直接生成漏洞结论。”
- “在 9 个历史 CVE fixture 上建立回归基准。”

- “已挖出 AC15 0-day。”

- “模型可完全自主确认漏洞，无需人工验证。”
