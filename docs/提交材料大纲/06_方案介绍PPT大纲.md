# FirmHound 方案介绍 PPT 大纲

> 定位：用于答辩或提交展示。建议控制在 12-16 页。老师给的两个 PPT 可参考“背景 -> 痛点 -> 方案 -> 架构 -> 创新 -> 实验 -> 商业/价值 -> 总结”的叙事结构，但内容必须换成 FirmHound 当前真实产品，不要照搬参考作品的数据和能力。

## 设计原则

- 评委不是来读论文的，PPT 要让人 3 分钟内明白产品价值。
- 每页只讲一个核心结论。
- 少放代码，多放架构图、流程图、结果表和真实截图。
- 不能把静态候选写成已确认 0-day。
- 对“CLI 而非 Web 平台”要主动解释：CLI 便于受控环境、可复现和自动化。

## 第 1 页：封面

标题建议：

FirmHound 固件猎犬：面向智能联网设备的可验证固件漏洞挖掘 CLI 智能体

副标题：

解包 -> 攻击面 -> 二进制审计 -> 证据验证 -> 报告生成

视觉建议：

- 深色科技背景。
- 左侧固件芯片/路由器图标，右侧“猎犬”视觉符号或证据链图。

## 第 2 页：背景 —— 固件正在成为关键攻击面

核心内容：

- IoT 设备广泛部署在家庭、城市、工业、能源和办公网络。
- 固件闭源、异构、长期维护不足。
- 固件漏洞发现和验证正在从“专家手工逆向”变成“自动化、合规化、证据化”需求。

图表建议：

- IoT 设备应用场景图。
- 固件在设备安全链路中的位置图。

## 第 3 页：痛点 —— 为什么固件漏洞挖掘难

四个痛点：

1. 解包难：非标准文件系统、加密、嵌套压缩。
2. 定位难：二进制无源码、架构异构、符号缺失。
3. 验证难：静态误报多，source/sink 不等于可利用。
4. 复现难：人工过程碎片化，证据链难沉淀。

图表建议：

- 四象限痛点图。

## 第 4 页：方案一句话

核心句：

FirmHound 把固件漏洞挖掘拆成可编排阶段机，用 Skill 知识库驱动确定性工具链，自动生成可追溯证据和报告。

图表建议：

- 一条横向流程：固件/rootfs -> 解包 -> 攻击面 -> 二进制 -> 候选 -> 反证 -> 报告。

## 第 5 页：系统架构

展示五层：

- CLI 交互层
- Orchestrator 决策层
- Tool 工具层
- Skill/Schema/Config 契约层
- Evidence/Report 产物层

讲解重点：

- CLI 不是简陋，而是更适合比赛受控环境和可复现流水线。
- 所有状态、证据、决策落盘。

图表建议：

- 五层架构图。

## 第 6 页：智能体阶段机

展示阶段：

INIT、BASELINE、UNPACK、SURFACE、BINARY_TRIAGE、DECOMPILE、STATIC_ANALYSIS、EXTERNAL_ANALYSIS、FUSION、SYMEX_PRUNE、RANK、VERIFY_TOP_K、LOCAL_VALIDATION、CONSTRAINED_VALIDATION、REPORT、DONE。

讲解重点：

- 每阶段有输入、输出和状态。
- 支持断点恢复。
- degraded 可继续，failed 才中止。

## 第 7 页：核心能力一 —— 固件解包与 rootfs 恢复

内容：

- binwalk 签名扫描。
- SquashFS/UBI/gzip 魔数切片。
- unsquashfs/sasquatch 解包。
- 加密固件识别。
- Windows symlink 容错。

案例：

- AC15 从 offset `0x1C9E98` 切出 SquashFS。
- BE3LPro 检测 OpenSSL Salted 加密载荷。
