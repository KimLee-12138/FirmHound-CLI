## 1. 开发背景与工程目标

### 1.1 工程目标

- 在比赛现场或实验室中快速分析授权固件。
- 保持 CLI 可运行、可测试、可恢复、可审计。
- 支持 Windows + WSL2 与 Linux 两类环境。
- 对外部重型工具缺失保持降级能力。

### 1.2 开发原则

- Schema 先行。
- 配置驱动，不硬编码路径与密钥。
- 结构化日志。
- 安全红线不可绕过。
- 工具必须返回 `ok/degraded/failed` 等结构化状态。
- 文档、Schema、示例同步。

## 4. CLI 入口实现

### 4.1 命令总览

当前命令：

- `fsa doctor`：本地环境自检。
- `fsa plan`：解析自然语言任务并生成计划，不执行分析。
- `fsa analyze`：正式分析入口。
- `fsa status`：查看运行状态。
- `fsa resume`：从中断阶段恢复。

### 4.2 参数设计

## 5. 编排器实现

### 5.1 核心类

- `Planner`：任务解析和计划构建。
- `Engine`：阶段机执行。
- `StateManager`：状态持久化和恢复。
- `HumanGate`：授权和人工确认。
- `ToolRegistry`：工具注册与调用。
- `SkillLoader`：读取 Skill 元数据。
- `EvidenceStore`：证据存储。
- `DecisionStore`：决策存储。

### 5.2 阶段机

列出全部阶段并解释每阶段输入输出：

| 阶段 | 作用 | 主要产物 |
|---|---|---|
| INIT | 初始化运行目录与任务 | task_card |
| BASELINE | 环境/授权基线 | state |
| UNPACK | 固件解包/rootfs 识别 | firmware_manifest/rootfs |
| SURFACE | 攻击面识别 | attack_surface |
| BINARY_TRIAGE | 二进制清单和风险初筛 | binary_summaries |
| DECOMPILE | 反编译/字符串/调用链辅助 | decompile artifacts |
| STATIC_ANALYSIS | source-sink 候选 | candidates |
| EXTERNAL_ANALYSIS | 外部分析器 | external_findings |
| FUSION | 主轨/外部轨融合 | unified_candidates |
| SYMEX_PRUNE | KLEE 反证/可达证据 | witness/counterevidence |
| RANK | 十维评分排序 | ranking |
| VERIFY_TOP_K | 反证验证 | verdicts |
| LOCAL_VALIDATION | 本地无害探针 | validation evidence |
| CONSTRAINED_VALIDATION | mini-BOND 约束验证 | constrained results |

## 6. 工具模块实现

### 6.1 firmware 模块

- `unpack.py`：binwalk 签名、carving、SquashFS/UBI/gzip/OpenSSL Salted 处理。
- `rootfs_score.py`：rootfs 可信度评分。
- `collect_info.py`：固件哈希、大小、基本元信息。
- `arch_detect.py`：架构识别。
- `build_manifest.py`：固件 manifest。

### 6.2 filesystem 模块

- 文件、脚本、配置、启动项清单。
- 容忍 Linux symlink 在 Windows 下不可访问的问题。

### 6.3 web 模块

- webroot 枚举。
- handler 提取。
- auth matrix。
- UPnP XML 解析。
- attack surface 构建。

### 6.4 binary 模块

- ELF 读取。
- 危险函数扫描。
- 二进制安全特征。
- 调用链和 triage。

### 6.5 analysis/audit 模块

- source/sink 规则。
- 数据流候选装配。
- 风险评分。
- 误报过滤。
- 排序与验证。

### 6.6 emulation 模块

- 动态验证安全门。
- qemu-user/qemu-system 包装。
- harmless probe。
- Firmae 检测与降级。

### 6.7 external 模块

- base adapter。
- SaTC parser/runner。
- FirmRec parser/runner。
- KLEE harness/parser/runner。
- BOND mini/runner/parser/sanitize。

## 9. 外部分析器扩展开发规范

新增外部工具时要求：

1. 新建 `tools/external/<tool>/`。
2. 实现 runner/parser/sanitize。
3. 继承或适配 base tool result。
4. 输出 `status`、`findings`、`limitations`。
5. 缺依赖时必须 `skipped/degraded`。
6. 加入 registry。
7. 增加 fixture。
8. 增加单元测试、融合测试和降级测试。
9. 更新 docs 和 Skill。

## 11. 安全开发规范

- 禁止硬编码路径和密钥。
- 禁止裸 `print` 做业务日志。
- 禁止绕过 safety policy。
- 禁止公网或未授权动态验证。
- PoC 和报告需通过 sanitize。
- 真实漏洞候选必须区分静态候选和确认漏洞。

## 12. 已知工程边界

- 真实 Ghidra/KLEE/BOND/FirmRec 依赖外部环境。
- BE3LPro 加密固件需要解密材料。
- CLI 是主产品形态，非在线 Web 系统。
- 通用网络安全智能体口径需要通过文档强调“固件漏洞挖掘垂直 Agent”。
