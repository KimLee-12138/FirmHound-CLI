# FirmHound 技术报告大纲

> 定位：技术报告要写出“为什么这个方法成立”。它不同于开发文档，重点是算法、证据模型、评分模型、外部工具融合、实验结果和局限性。

## 0. 摘要

建议摘要结构：

1. 固件漏洞挖掘存在解包、攻击面恢复、跨函数关联、误报验证等难点。
2. FirmHound 提出 CLI 智能体流水线，将 Skill 知识、确定性工具、阶段机和证据链结合。
3. 系统实现固件解包、攻击面构建、二进制审计、十维评分、反证验证、外部工具融合和安全动态验证。
4. 在 9 个历史 CVE fixture 和 3 个真实固件样本上进行了验证。
5. 结果表明系统具备可运行、可解释、可降级能力；真实确认漏洞仍需动态验证与人工复核。

## 3. 固件解包与 rootfs 识别方法

### 3.1 签名识别

- binwalk 签名扫描。
- 兼容经典三列表格和 `|` 表格。
- 超时控制，避免交互模式悬挂。

### 3.2 文件系统切片

- 根据 SquashFS、UBI、gzip、OpenSSL Salted 等魔数切片。
- 对 SquashFS 切片调用 unsquashfs/sasquatch。
- 判断“返回成功但目录为空”为失败。

### 3.3 rootfs 评分

评分依据：

- `bin/`
- `etc/`
- `usr/`
- `www/htdocs/webroot_ro`
- init 脚本
- ELF 数量

### 3.4 加密固件处理

以 BE3LPro 为例：

- 识别 OpenSSL encryption salted。
- 保存加密载荷切片。
- 输出需要解密材料的失败原因。
- 不伪造 rootfs 和漏洞结果。

## 6. 风险评分模型

### 6.1 十维评分

写清楚 P-I-U-D-C-S-W-K-V-T 每一维的含义。建议命名：

- P：Pre-auth 暴露程度
- I：Input controllability 输入可控性
- U：User control 用户控制度
- D：Dangerous sink 危险函数
- C：Concatenation/transform 拼接或变换风险
- S：Sanitization/validation 过滤情况
- W：Web reachability Web 可达性
- K：Known risky pattern 已知危险模式
- V：Validation evidence 验证证据
- T：Traceability 调用链可追踪性

如果代码里的维度名称有最终定义，文档需和代码同步。

### 6.2 风险等级

- CRITICAL
- HIGH
- MEDIUM
- LOW

### 6.3 评分解释

每一维都应有证据或为 0，避免无证据加分。

## 7. 反证验证模型

### 7.1 为什么需要反证

静态扫描容易产生误报，不能只靠 source/sink 共现确认漏洞。

### 7.2 10 问验证清单

包括：

1. 输入是否来自外部。
2. 攻击者是否可控。
3. 是否到达危险函数。
4. 中间是否过滤。
5. 调用链是否可达。
6. 程序是否启动。
7. 是否需要认证。
8. 是否调试功能。
9. 是否平台条件限制。
10. 是否存在矛盾证据。

### 7.3 五类结论

- confirmed-issue
- high-confidence-candidate
- false-positive
- unknown
- observation

## 8. 外部工具融合方法

### 8.1 SaTC

用于跨函数污点增强。

### 8.2 FirmRec

用于复发漏洞检测，必须和 Blind Run 隔离。

### 8.3 KLEE

用于可达 witness 和不可达反证。

### 8.4 mini-BOND

用于约束导向的授权仿真验证。

### 8.5 融合策略

- 主轨候选 + 外部同证据：提高置信。
- 外部独有发现：转为新候选进入验证。
- FirmRec：单独 recurrence findings，不进入零先验统一候选。
- 不可达证据：作为 counterevidence，不直接声明安全。

## 12. 讨论与局限

必须写清楚：

- 静态候选不是确认漏洞。
- 加密固件需要额外解密材料。
- 泛化到渗透测试/应急响应需要额外场景扩展。
- 外部工具实测依赖主机资源。
- 模型 API 合规接入需要主办方网关和国内备案模型。

## 13. 结论

总结：

- FirmHound 已形成可运行 CLI 产品。
- 工程上具备 CI、测试、Schema、报告和安全策略。
- 技术上具备固件解包、攻击面建模、二进制分析、候选生成、评分验证和证据输出。
- 后续应补齐真实动态验证、在线可测/一键部署和答辩材料。
